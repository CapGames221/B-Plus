1Что такое B+

B+ — это язык программирования, который превращает ваш код прямо в готовую программу для Windows (.exe или .dll). В отличие от многих языков, B+ не использует внешние компиляторы, ассемблеры или линкеры — весь процесс сборки выполняет собственный компилятор, написанный с нуля на Zig.

Код хранится в файлах example.b+. В B+ два режима:

PLAN — логика состояний

Меню игры, состояния персонажа, игровые режимы, сетевые протоколы, обработчики событий.

METAL — функции и данные

Процедурный код: функции, переменные, структуры, if/while/for, арифметика, print.

x64 Windows PEСвой кодогенераторБез LLVM/линкеровОптимизации

2Установка и сборка

Требования

  • Windows x64
  • Zig 0.14.0
  • Git (для разботы с репозиторием)

Сборка из исходников

git clone https://github.com/bylka2W/B-Plus.git
cd zig
zig build

Готовый исполняемый файл: zig-out\bin\bpc.exe

Проверка установки

Автозапуск после установки

Флаг --install-path <dir> в команде bpc doctor прописывает путь к компилятору в системные настройки (автозагрузка) для дальнейшего удобного запуска.

4PLAN — логика состояний

Программа описывается как машина состояний: состояния и переходы между ними по событиям.

state Locked {
    on open [key == 1] -> Opened
    entry {
        print("locked")
    }
}

state Opened {
    on close -> Locked
    entry {
        print("opened")
    }
}

Состояния

state Locked { ... } — блок с переходами. Идентификаторы без типа внутри состояния — автоматические переменные i64.

Переходы

on <событие> [условие] -> <состояние>. В теле перехода можно записывать значения в переменные.

entry / exit

entry { } — код при входе в состояние, exit { } — при выходе.

Валидация

Проверяется согласованность состояний, событий и переходов (bpc check).

Примеры PLAN (machine/state) проходят проверку bpc check, но автономный запуск требует функции fn main(). Планировщик состояний подключается из рантайма.

5METAL — функции и данные

5.1 Точка входа и print

fn main() {
    print(42);
    print("hello");
}
print выводит целые (i64/u8/u16/u32/i32…), вещественные f64, строковые литералы и булевы значения (true→1, false→0). Функция print_i64 отсутствует — используйте print.

5.2 Функции

fn add(a: i64, b: i64) -> i64 {
    return a + b;
}

fn main() {
    print(add(3, 4));
}

Возврат значения — только через явный return. Функции работают до/после объявления, поддерживается рекурсия.

5.3 Переменные

var x: i64 = 42;   // тип + значение
var y;           // без типа (i64, значение по умолчанию 0)
var z = 10;       // вывод типа
x = 10;           // переприсваивание

5.4 Структуры

struct Point {
    x: i64,
    y: i64,
}

var p: Point;
p.x = 10;
p.y = 20;
print(p.x);

if x > 5 { print(1); } else { print(0); }

var i: i64 = 0;

1What is B+

B+ is a programming language that turns your code directly into a ready-made Windows program (.exe or .dll). Unlike many languages, B+ does not rely on external compilers, assemblers or linkers — the entire build is performed by its own compiler written from scratch in Zig.

Code lives in example.b+ files. B+ has two domains:

PLAN — state logic

Game menus, character states, game modes, network protocols, event handlers.

METAL — functions & data

Procedural code: functions, variables, structs, if/while/for, arithmetic, print.

x64 Windows PEOwn codegenNo LLVM/linkersOptimizations

4PLAN — state logic

A program is a state machine: states and transitions between them driven by events.

state Locked {
    on open [key == 1] -> Opened
    entry {
        print("locked")
    }
}

state Opened {
    on close -> Locked
    entry {
        print("opened")
    }
}

States

state Locked { ... } — a block with transitions. Untyped bare identifiers become automatic i64 variables.

Transitions

on <event> [condition] -> <state>. Transition bodies can write values to variables.

entry / exit

entry { } — code run on entering a state, exit { } — on leaving it.

Validation

State/event/transition consistency is validated (bpc check).

PLAN examples (machine/state) pass bpc check, but standalone running requires a fn main(). The state-machine scheduler is wired from the runtime.

5METAL — functions & data

5.1 Entry point and print

fn main() {
    print(42);
    print("hello");
}
print outputs integers (i64/u8/u16/u32/i32…), f64 floats, string literals and booleans (true→1, false→0). There is no print_i64 — use print.

5.2 Functions

fn add(a: i64, b: i64) -> i64 {
    return a + b;
}

fn main() {
    print(add(3, 4));
}

Returning a value requires an explicit return. Functions work above/below their call site; recursion is supported.

5.3 Variables

var x: i64 = 42;   // type + value
var y;           // no type (i64, defaults to 0)
var z = 10;       // type inference
x = 10;           // reassignment

5.4 Structs

struct Point {
    x: i64,
    y: i64,
}

var p: Point;
p.x = 10;
p.y = 20;
print(p.x);
